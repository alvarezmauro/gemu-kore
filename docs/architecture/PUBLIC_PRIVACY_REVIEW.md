# Public privacy review

Task **18.7** · 2026-10-21 · Baseline `1f9a48d`

Status: **Complete.** One low-severity indexing-policy contract gap was reproduced and fixed. No private-data disclosure or role-escalation bypass was reproduced in the reviewed Phase 18 application paths.

## Finding and correction

**PRIV-01 — Low severity, indexing-policy normalization.** A record-schema parse discarded an own `__proto__` query key. At the SEO service boundary, an explicitly parameterized request could consequently look empty and receive `index: true` when indexing was enabled. This did not select private fields or bypass publication/media approval. Added a pre-parse rejection so the service returns generic noindex metadata without canonical or image output. The PostgreSQL regression reproduced `index: true` before the fix and covers home, category and item metadata. [Fix](../../src/server/services/public-collection/seo.ts), [regression](../../tests/integration/public-collection.test.ts).

The browser's public-search response to this key is a separate framework behavior: the installed Next.js query-object conversion removes it before reconstructing the Route Handler URL. Public browse validation rejects the key when it reaches the application; individual prototype-looking controls now have regressions. The HTTP probe compares the normalized response with the ordinary public listing and checks that it grants no extra data or authority. Other unknown audience/role/visibility controls still return generic 400s. No private-data disclosure or privilege escalation was reproduced in this case.

Prefetch is also distinct from reading an item: the installed Next.js version can return a deferred route tree with status 200. The withdrawal probe follows prefetch with an actual Flight request and page navigation, requiring a not-found payload and generic unavailable UI with no withdrawn title. Next.js documents [different not-found status codes for streamed and non-streamed output](https://nextjs.org/docs/app/api-reference/file-conventions/not-found); status alone is not the privacy assertion. Authorization at each independently callable server entry point follows the [Next.js authentication guidance](https://nextjs.org/docs/app/guides/authentication).

## Scope and method

The reviewed story is an anonymous or signed-in visitor opening the museum, searching published physical copies and requesting approved images or on-demand 3D: public page/API → public service → current database policy and narrow repository projection → HTML/Flight/JSON or contextual storage delivery. Private management, publication commands and original downloads remain separately authorized operations.

Reviewed [PROJECT_SPEC.md](../../PROJECT_SPEC.md) §§10–12, 54–61, 69, 79–86, 109, 123–124, 129–133 and 135, the [public privacy architecture](PUBLIC_PRIVACY_ARCHITECTURE.md), public/private HTTP adapters, feature queries, Server Components, client props, search SQL, publication/media commands, database guards, viewer contracts and response caching. The review treats URL parameters, headers, roles, cookies, IDs and action arguments as untrusted. A trusted operator deliberately changing database rows is outside the application authorization boundary.

## Targeted adversarial evidence

Added [browser probes](../../tests/access-e2e/public-privacy.spec.ts) and a [disposable canary fixture](../../tests/helpers/public-privacy-data.ts). A shared source original contains a unique marker in bytes, filename and raw metadata; its opaque source/display locators are checked separately. Its explicitly approved sanitized display omits the marker. Approved, unapproved, SERIAL and private-copy uses share that file; the site logo has its own approval. A separate canonical provider snapshot and defect repair notes contain the marker. The checks inspect complete HTML, full Flight and prefetch payloads, JSON, whole/component descriptors, robots and sitemap output for anonymous and all three roles. They also exercise stored script text, direct binary/HEAD/range/conditional requests, optimizer attempts, use-kind substitution, private endpoints, forged authority headers and requests after withdrawal.

Three additional [PostgreSQL integration cases](../../tests/integration/public-collection.test.ts) cover site-logo authority, private/unapproved uses of the same approved output, and deterministic concurrent input-rights withdrawal. The concurrency case pauses an already established public snapshot, commits revocation and checks that fresh media/detail/SEO reads deny the image while the admitted snapshot retains its previous view. Existing cases continue to cover settings/write serialization, stale review rejection, revoked administrators, conditional field selection, bounded search/count/facet reads and component approval resets.

## Limits and disposition

This is an application review of the implemented public boundary, not a proof about every possible deployment or future feature. Previously admitted snapshots, already delivered bytes and external search copies cannot be recalled. Human content review must still exclude identifying pixels, labels and embedded textures; the canary fixture demonstrates exact display/source separation, not automatic semantic redaction. The tests use disposable PostgreSQL/MinIO and signed fixture sessions; no personal database, live provider credentials or real collection publication is changed.

The indexing correction and regression evidence resolve the review's application finding. No architecture change, production dependency, schema migration or future roadmap feature is part of this review. Phase 19 remains unstarted.
