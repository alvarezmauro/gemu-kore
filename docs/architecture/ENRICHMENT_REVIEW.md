## Findings and corrections

### M01 — Contradictory choices could share a selection ID

The normalized output validator checked evidence IDs and release-observation keys but did not require unique candidate/trailer identities. Raw search mapping already rejected duplicate game IDs; that check was absent at the independently injected adapter boundary. Trailer mapping deduplicated complete values, so two videos with the same provider VIDEO ID but different titles/YouTube IDs survived. The preview submitted only that ID, while proposal preparation selected its first matching record. A reviewer could therefore see a choice whose submitted identity resolved to a different video.

**Correction:** the shared runtime validator now rejects repeated provider/object-type/external-ID identities in search and trailer choices. This runs at mapping, runner publication and retained-result reads. Contradictory evidence fails with a sanitized invalid-response outcome before a usable result or proposal is published. No heuristic chooses a winner. New unit cases reproduce both normalized collisions and the raw trailer collision; database cases prove these failures leave canonical revision/history untouched.

Evidence: [runtime validation](../../src/server/providers/game-metadata/contracts.ts), [mapping regressions](../../src/server/providers/game-metadata/igdb-mapping.test.ts), [service regressions](../../tests/integration/enrichment.test.ts).

### M02 — Incomplete evidence was retained but hidden in the preview

The adapter retained `limited`/`invalid` section states and bounded diagnostics. The private review projection discarded that information, so a truncated or partly invalid developer, trailer or playtime set appeared without an explanation of its limits. Preserving existing relationship entries prevented deletion by omission, but reviewers still needed to know that the supplied evidence was incomplete before choosing or accepting it.

**Correction:** the service now derives a bounded list of fixed, readable warnings from retained search/metadata state. The preview displays **Evidence limitations** before its choices and comparisons. Warnings cover incomplete search context, identity diagnostics and limited/invalid description, company, trailer and playtime sections. They expose no raw diagnostic text and do not invent facts, remove valid evidence or change overwrite permissions. They are derived from immutable retained results, so they remain available after preparation, acceptance and reload without another provider call. Existing runs need no source-snapshot rewrite or migration.

Component checks exercise the warning before and after preview preparation. A database regression applies partial evidence with explicit acknowledgements, preserving an existing manual alias and developer credit and retaining the complete proposed playtime group's unknown estimate. The production browser journey verifies the same limitations for an editor and accepting administrator.

Evidence: [warning projection](../../src/server/services/enrichment/evidence-warnings.ts), [private review](../../src/server/services/enrichment/suggestions.ts), [preview](../../src/features/enrichment/components/enrichment-review.tsx), [browser journey](../../tests/access-e2e/enrichment.spec.ts).
