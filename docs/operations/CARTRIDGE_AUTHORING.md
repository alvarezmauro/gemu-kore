# Private cartridge authoring

Task 14.4 adds the first `PHYSICAL_MEDIA` renderer: a reusable authored cartridge GLB with one explicit `FRONT_LABEL` artwork surface. `PhysicalMediaTemplate`, `PhysicalMediaTextureSlot` and `PhysicalMediaTextureBinding` are separate from packaging tables. They share bounded geometry/artwork helpers, private delivery and the existing viewer stage. This increment does not infer a shell or label from a game platform, cover or packaging assignment.

## Curate a cartridge

1. Open **Game catalog → Game releases → Manage release cartridges**. Add a `MEDIA` expected component to the release first. Separate cartridges with distinct identities or labels need separate components; quantity describes interchangeable expected instances and does not create duplicate meshes.
2. Expand **Create cartridge template**. Enter a variant name, unique slug, family revision, measured X width/Y height/Z depth in millimeters and their source. Mark demonstration dimensions synthetic. One initial `cartridge` family is admitted; console/market suitability is a curator decision, not an inferred property.
3. Enter **Artwork surface mappings (JSON)** with exactly one `FRONT_LABEL` target. Supply scene/node/mesh/primitive/material indices, matching diagnostic names, UV0 and physical label width/height. The initial form requires dimensions and mapping at draft creation. Create the draft, then **Upload cartridge geometry**, retaining known source, author, license, attribution and restrictions.
4. Download and review the private model. Check the actual silhouette, molded details, label recess/surface, connector, measured dimensions, source and mapping. Confirm the review checkbox and mark ready. The server hashes and inspects stored bytes outside the write transaction, then rechecks current permission, template revision and model identity under the catalog guard. Numeric checks cannot establish historical accuracy or rights.
5. Choose the ready template on the release's expected media component. Upload release artwork separately, select it for **FRONT LABEL**, set an explicit normalized crop and clockwise quarter-turn, then save. Art is proportionally contained with neutral margins. Missing art remains neutral and is labeled incomplete. No cover-to-label inference or automatic binding occurs.
6. On an owned game's **Physical edition** section, select an expected component and activate **View in 3D**. Packaging and media share one selector and one viewer. A component switch closes the old session before another is activated. Front/back views, keyboard/touch, fullscreen, reduced motion and safe fallback reuse the existing controls.

Previews show expected catalog geometry/artwork. They do not confirm that a cartridge is present or show this copy's condition. Owned component presence and primary-package controls remain inactive, and manual `hasBox` answers remain unchanged.

## Readiness, revisions and private delivery

Only current administrators create templates, upload geometry/artwork or change assignments. Current private readers can load previews and private files. Source metadata is retained but does not grant public publication. Component `presentationApproved` remains false. Private descriptors omit storage keys, measurement notes and curator identities.

A dedicated `physicalMediaGeometry` upload target attaches an original GLB directly to a draft through a version-2 manifest; it creates no catalog artwork or console-model use. Legacy v1 and packaging v2 uploads remain compatible. Uploads require the displayed draft revision, reauthorize on completion, and protect an already ready model. Replacing draft geometry explicitly advances its revision. An old upload cannot complete over its replacement. If a response is uncertain and its upload ID is available, use **Check pending upload**. Otherwise refresh before retrying a file.

Ready geometry, dimensions, metadata, camera/material contracts and slot mappings are immutable. Corrections need a new family revision and explicit reassignment. Archiving prevents new assignments while retaining existing previews; restoration reopens selection. Template/slot/model/label relationships are protected by foreign keys, database guards and asset-family cleanup checks.

Assignment, bindings, release revision and metadata history commit together. Identical saved snapshots are idempotent; stale conflicting saves retain form entries and require refresh. Ordinary catalog edits preserve assignments and reject removing an assigned media component or changing its kind until explicitly detached. A template or label assignment on one release never changes another release's artwork. Switching templates starts an empty binding set; saving without a template explicitly detaches the label.

## Geometry and label contract

Use a self-contained static GLB with one default scene (index 0), meter units, +Y up and front along +Z. Bounds must match supplied dimensions within 2% or 1 mm per axis, whichever is larger. Curators supply a truthful cartridge silhouette; the application does not turn a cuboid into a cartridge by naming it.

The initial profile requires opaque single-sided PBR materials. No embedded images/textures, external resources, alternate scenes, animation, skinning, morphs, sparse accessors, vertex colors, extensions or extras are admitted. Replaceable label material is neutral white, opaque and non-emissive; no other game's artwork may be baked into unbound geometry. Housing retains its original reviewed material when the label is replaced.

`FRONT_LABEL` is exactly two outward-facing triangles forming a full rectangular UV0 island. UV (0,0) is the top-left corner, +U/right is +X and image up is +Y. Face normal is +Z. Declare the physical art rectangle size independently of the shell dimensions. Indices resolve the exact node/mesh/primitive/material; names are diagnostics. Shared original materials and nested/multi-primitive nodes use the same tested association/cloning path as authored packaging. A back label, disc art, game card or alternative UV profile needs a later deliberately implemented contract.

Existing budgets remain: 8 MiB geometry, 12 MiB combined model/unique artwork transfer, 2 MiB per image, 2,048-pixel source edges, 8 million source pixels and 1,024-pixel composite edges. Existing node/triangle/draw/geometry/material/texture budgets include the cloned label material. Two transfer workers share 60 seconds; parsing/composition share 10 seconds. MIME, streamed lengths, dimensions and image headers are validated before decoding. Close, component switch, failure, cancellation and late decoding release geometry, original/cloned materials, textures, bitmaps and canvas backing stores. Sessions do not share mutable label maps or retain a model/texture cache.

## Synthetic fixture and migration

`pnpm three:fixtures` writes `test-results/three-fixtures/synthetic-cartridge.glb` and its complete `synthetic-cartridge-slots.json`. This original study has **synthetic 104 × 72 × 19 mm** dimensions and a 76 × 38 mm front label. It models a stepped beveled shell, grip ribs, recessed connector and synthetic contacts. It contains no retail branding, copyrighted label or asserted retail measurements. Mark it synthetic and retain that evidence when curating it. Fixture generation does not seed production catalog data.

Apply migration `20261020160000_cartridge_renderer` through the normal migration workflow. It adds media tables, composite same-template relationships, eligibility/readiness/freeze/kind guards, asset references and indexes while preserving existing packaging rows and manual copy answers. The type enum represents CARTRIDGE/DISC/CARD/OTHER, but this migration and application admit only the implemented CARTRIDGE profile. Other media types are not enabled by their representability.

Task 14.5 may expand supported cartridge template metadata when requested; it does not redesign the renderer. No opening animation, optical refraction, owned presence, primary-package selection, nested inventory or public presentation is activated here. Tests use disposable PostgreSQL/MinIO; the personal development database is not migrated.
